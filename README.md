# CF7 Spam Blocker

Contact Form 7 用の迷惑メールブロッカー。複数のWordPressサイトの迷惑メール対策を、1つのブロックリストで一括管理できます。WordPress.org 非登録の自前配布で、プラグイン本体の更新は GitHub Releases 経由で全サイトに通知されます。

## 構成

```
cf7-spam-blocker/        ← プラグイン本体（各サイトにインストール）
.github/workflows/release.yml ← タグpushでzipビルド＆Release自動作成
build.sh                 ← 手動インストール用zip作成スクリプト
```

## ブロック仕様

- **メール欄** (`email` / `email*`): 拒否ドメインとの完全一致（サブドメイン含む）でブロック
- **テキスト・本文欄** (`text` / `textarea`): 拒否ドメインまたは拒否文字列（会社名など）が含まれていればブロック
- 各サイトは送信判定のたびにリストの鮮度を確認し（キャッシュ60秒）、どこかのサイトでの変更がほぼ即時に全サイトへ反映されます。バックアップとして1時間ごとの自動取得（wp-cron）も併用。取得失敗時は前回のリストで動き続けます
- 秘密キーを設定したサイトの管理画面からリストを編集でき、中央サーバーに保存 → 同じリストを参照する全サイトに反映されます

## Turnstile の送信失敗を防ぐ（2.19.0〜）

CF7 の Turnstile（Cloudflare のロボット確認）を有効にしているサイトでは、確認の値が空・期限切れ（約5分）のまま送るとスパム判定になり、利用者には「メッセージの送信に失敗しました」とだけ表示される（見えない形のウィジェットでは利用者が直せない）。このプラグインを入れると、全フォームで次を行う（設定は不要。CF7 の Turnstile が有効なときだけ動く）。

- 送信の直前：確認の値が空か4分より古ければ、取り直してから送る（ボタンは「送信の準備をしています…」）
- スパム判定になったら：確認を取り直して1回だけ自動で送り直す（ブロックリストによる拒否は送り直さない）
- Turnstile の検証に失敗した送信を `cf7sb_turnstile_log` に記録（件数と最近50件。送り直しで送れたものは `recovered`）。確認：`wp option get cf7sb_turnstile_log --format=json`
- 止めるとき：`add_filter( 'cf7sb_turnstile_guard', '__return_false' );`
- （2.20.0〜）確認のウィジェットを「必要なときだけ表示」（data-appearance=interaction-only）にし、CF7 がフォームの先頭に足したものは送信ボタンの直前へ移す。**Cloudflare 側でウィジェットのモードを「管理（Managed）」にすると**、確認が自動で通らない環境（ブラウザの偽装・拡張機能など）でも送信ボタンのすぐ上にチェック欄が出て、利用者が自分で済ませられる（ふだんは何も表示されない）。チェックせずに送信すると、送らずに「すぐ上の確認（チェック）を済ませてから、もう一度送信してください。」と案内する。「非表示（Invisible）」のままのサイトでは見た目は変わらない。置き場所を変えたくないときは `cf7sb_turnstile_place` を false に

## 初回セットアップ

### 1. GitHubリポジトリ（プラグイン本体の配布・更新用）

1. GitHubの **パブリック** リポジトリ [hiroshiy1227/tool-wp-spamblocker](https://github.com/hiroshiy1227/tool-wp-spamblocker) にこのディレクトリをpush
2. リポジトリを移動・改名した場合は、`cf7-spam-blocker/cf7-spam-blocker.php` ヘッダーの `Update URI:` を新しいリポジトリURLに合わせる

### 2. 1サイト目

1. [最新Releaseのzip](https://github.com/hiroshiy1227/tool-wp-spamblocker/releases/latest) を「プラグイン → 新規追加 → プラグインのアップロード」からインストール・有効化（初回のみ手動。以降はGitHub経由で更新）
2. 「設定 → CF7 Spam Blocker → 初期セットアップ」タブで「**このサイトを中央サーバーにする**」ボタンを押す

これだけです。プラグイン自身がWordPressのREST API（`/wp-json/cf7sb/v1/list`）でリストを配信するため、**外部ファイルの設置・FTP・キー管理は不要**です。リストはこのサイトのDB（wp_options）に保存されます。

### 3. 2サイト目以降

1. zipをインストール・有効化
2. 中央サーバーにしたサイトの「初期セットアップ」タブで**セットアップコードをコピー**し、新しいサイトの「接続設定」タブに貼り付けて保存

- `?list=会社A` のようにリスト名を変えると、用途別（会社A用・会社B用・個人用など)に別リストを共有できます
- 秘密キーを空にすると、そのサイトは閲覧・自動取得のみ（編集不可）になります

## リストの編集

どのサイトでも「設定 → CF7 Spam Blocker」で拒否ドメイン・拒否文字列をタグ形式で追加（「＋ 追加する」ボタン）・削除（タグの×）し「保存」するだけです。中央サーバーに保存され、同じリストを参照する他サイトにもほぼ即時に反映されます（各サイトが送信判定のたびに鮮度確認・キャッシュ60秒）。

## バージョンアップの出し方（Git経由）

1. コードを修正し、`cf7-spam-blocker/cf7-spam-blocker.php` の `Version:` ヘッダーと `CF7SB_VERSION` 定数を上げる
2. コミットしてタグをpush

   ```bash
   git add -A && git commit -m "v1.1.0"
   git tag v1.1.0
   git push origin main --tags
   ```

→ GitHub Actionsが自動でzipをビルドしてReleaseを作成します（タグとVersionが不一致だと失敗して教えてくれます）。各サイトの管理画面（プラグイン一覧）に更新通知が出て、ワンクリックで更新できます。自動更新を有効にすれば自動適用されます。

更新チェックの結果は最大6時間キャッシュされます。すぐ確認したい場合は各サイトの「ダッシュボード → 更新 → 再確認」。

### 補足

- アップデーターは `Update URI:` がGitHub以外のURLの場合、そのURLを `info.json`（`version` / `package` を持つJSON）として参照する自前サーバー方式でも動作します。
